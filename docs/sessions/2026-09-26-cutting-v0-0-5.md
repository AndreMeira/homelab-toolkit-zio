# Cutting v0.0.5

The first release carrying the LLM modules, and the first with a breaking change in `common`. This records
the pre-flight, because a GitHub Packages version cannot be overwritten once pushed and the checks worth
running are not obvious from the workflow.

## What the release contains

Three new published artifacts — `homelab-llm`, `homelab-llm-openai`, `homelab-llm-anthropic` — taking the
published set from five to eight. Plus, in `common`:

- **breaking:** `Workflow.Step.Pending` became `Step.Current`, and `next` answers `Step.Next[S, O]` rather
  than `Step[I, S, O]`
- **added:** `Consumer.fromKeyedQueueWithKeys`

## The pre-flight

Three checks, in the order that matters:

**Is every module actually in the aggregate?** `publish` runs on the root, which aggregates. A new module
that nobody added to `.aggregate(…)` compiles, tests, merges and is then silently missing from the release
— and the release looks successful. `sbt "print publish/skip"` lists every module and its answer, which is
the direct way to see what will be pushed.

**Does it package?** `RELEASE_VERSION=<something> sbt publishLocal` builds every artifact with its jar,
sources, javadoc and pom against a release-shaped version. The CI workflow runs `test` then `publish`, so
a packaging failure is only discovered after the release exists and the tag is cut.

**What changed in the modules that already had consumers?** The new artifacts cannot break anyone. The
existing ones can, and the auto-generated notes are a list of PR titles that will not say so. Diffing
`v<previous>..main` over the published modules is what surfaced the `Workflow` change.

## On the notes

GitHub's generated notes went in, under a hand-written preamble leading with the breaking change. A
consumer upgrading reads the top of the release, not nine PR titles — and "inlining lambdas" does not
communicate that `Step.Pending` no longer exists.

The notes also state plainly that no call has ever been made to a real provider, so the LLM artifacts are
untested against live APIs. A release is where that belongs: it is the first point at which someone who
was not in the conversation can depend on the thing.

## Versioning

Weighed `0.1.0` against `0.0.5` — three new artifacts and a source break is the strongest argument for a
minor bump this repo has had. Kept `0.0.5` for consistency with the existing rhythm. The consequence is
that the version list does not distinguish this release from the four before it, so the notes have to.

## Left behind

`release.yml`'s header comment says it publishes "the five library modules". It is eight, and has been
since the LLM modules landed.
